# Occuris Echo

**A voice-first agent for people with motor or vision impairments. One sentence → Gmail, Google Calendar, Slack and a Google Sheets ledger → the agent tells you exactly what it did.**

> **Demo video:** https://www.loom.com/share/413c0668620e448c8b2e869cd1f1176e
> **Results:** 57/57 known-answer cases pass · **0 silent failures** · 0 over-clarifications · with the deterministic layer disabled: **3 silent failures** → [RESULTS.md](RESULTS.md)

Built solo in the Multi-App AI Agent Hackathon window, 13 September 2026. Spec and test fixtures were written in advance; all code was written during the event.

---

## The problem

Say you have a tremor, or low vision, or you use a screen reader. Replying to your doctor, putting the appointment on your calendar, and telling your sister — that's three apps and forty-odd precise clicks. An AI agent can do it in one sentence. But now there's a worse problem: **you can't easily check whether it did it right, and you can't afford ten clicks to undo it.** An agent that emails the wrong Patel, books lunch at 7pm when you said 2, or reports "done" when Slack actually failed is *invisible* to exactly the user who needs it most.

So Echo's whole design is about one thing: **never being confidently wrong.**

## What it does

Say: *"Reply to Dr. Patel that Thursday at 2 works, put it on my calendar, and tell my sister."*

Echo:
1. Parses it with **deterministic rules first** (contacts lookup, date rules, correction markers, disfluency stripping). The model is only asked about what the rules can't settle, and everything it contributes is tagged `score_source: model`.
2. **Asks one question instead of guessing** when something is ambiguous — two contacts called Patel, "next Thursday" said on a Thursday, a garbled word.
3. **Confirms before anything irreversible.** Email and Slack wait for your "yes"; calendar events and trusted-contact messages go straight through.
4. **Acts across four apps**, with an idempotency key on every action — say "send it again" and it says *"I already sent that."*
5. **Echoes back what actually happened**, generated only from the action statuses — never from what you said. Partial failures are stated: *"Email sent. Calendar done. Slack failed — nothing went out there."*
6. **Answers "am I free?"** — *"Do I have anything on Friday?"* lists the day. *"Any slots for a concert Friday?"* gives the evening windows first, then the daytime ones; *"coffee"* leads with daytime. Read-only, so it never needs a confirmation.
7. **Remembers for you.** Add something similar to what's already there and it asks *"You already have 'Dentist' Friday at 10 — same one, or different?"* — "same" updates it instead of duplicating. *"It's not a lunch, it's a dinner"* renames what it just added. *"The dentist you put on Friday, change it to 11"* edits by reference. And it **never deletes anything** — "cancel the dentist" marks it *Cancelled —* and leaves it visible; "delete" gets an offer to change it instead.

It also handles the sentence a real user actually says: *"I have a lunch umm at around like 7 not 7 UMM actually at 2:00 PM…"* — it books **2pm**, and the echo tells you so.

| A · clean commands | 19 | 19 | 0 | 0 |
| B · adversarial | 30 | 30 | 0 | **3** |

| D · read-side ("what do I need to do this week?") | 4 | 4 | 0 | 0 |

- **Silent failure** = committed to a wrong value where it should have asked, or claimed "done" for something that didn't happen. The one metric that matters for a user who can't check.
- **Ablation**: switch the deterministic layer off and the same agent guesses the first Patel (B1), guesses John over Joan (B2), and books lunch at **7pm instead of 2** (B17). That gap is the architecture.
- Each fixture is scored **per step** — intent, slots, gate, actions, read-back — so a failure says *where* it failed.
- Fixtures run against **in-memory twins** of all four apps, seeded from scenarios and resettable; assertions are on **twin state** (event counts, sent-mail counts, ledger rows), never on what the agent claims.
- **Eleven fixtures came from real testing** — three the night before and eight during the build, from the builder talking to it the way a real user does: rambling multi-sentence requests, ASR fragments ("Book me. For lunch on 3:00 PM. Wednesday…"), corrections mid-conversation ("not Wednesday, Thursday"; "it's actually Ravi Patel" after the email had gone — it says it can't unsend and offers to fix it). Including three that were once: a mishear ("remind" → "required"), a spelled-out "U-M-M", and the self-correction above.

## Architecture

```
voice (Web Speech API) ─┐
text box (fallback)     ─┴─> parse ──> gate ──> providers ──> echo
                             │          │           │
              deterministic first       │     twins  (harness)
              model fallback, tagged    │     real   (demo)
                                 CONFIRM_REQUIRED / AUTO_OK / BLOCKED
```

- **`echo/parse.py`** — rules: contacts resolution with ambiguity detection, weekday/time rules, `not 7 … actually 2` corrections (last value wins), disfluency stripping, clause splitting for multi-intent sentences.
- **`echo/model.py`** — Claude, called only when rules produce nothing. It extracts *mentions*; resolution still goes through the deterministic layer, so a model mistake becomes a question, not an action.
- **`echo/agent.py`** — the gate, idempotency keys, retries with backoff, and **derived pending state**: "what's waiting for a yes" is computed from the ledger (requested − completed), never stored as a flag. A crash mid-run loses nothing; the pending card survives a reload.
- **`echo/readback.py`** — the echo is built from slots and action statuses only. Dates are spoken in full ("Thursday the seventeenth of September at two pm").
- **`echo/providers/`** — one interface, two implementations. `twins.py` (in-memory, seeded, failure-injectable) and `real.py` (Gmail, Calendar, Slack, Sheets).
- Every run emits a **trace**: transcript → intent → slots with `score_source` → gate → each provider call with status and latency → read-back. `GET /traces` returns the last ten.

### Memory
Semantic memory is the **contacts sheet** (who "my sister" is, who's trusted, which channel). Episodic memory is the **ledger sheet** — it's what makes "did I already send this?" answerable. The gate pipeline is procedural and fixed. There is deliberately **no retrieval memory**: nothing here needs similarity search, and a vector store would add a failure mode we couldn't measure.

### Scopes
`gmail.readonly`, `gmail.send`, `calendar.events`, `spreadsheets`, Slack `chat:write` + `users:read`. **No delete capability on any app.**

## The interface

Built to [DESIGN.md](DESIGN.md): 60px+ targets, no drag, no hover-only controls, no timeouts, `aria-live` read-back region, every status carries icon + word + colour (Okabe–Ito hues), no ambient motion, warm-paper default with a Dusk theme for photophobia, voice and speed selectable. **Nothing is sent until you say yes** is on screen before you do anything.

## How to run

```bash
pip install -r requirements.txt

# sandbox — no credentials, in-memory twins, safe to poke
ECHO_TWINS=1 python server.py        # → http://localhost:8000

# real — needs .env (see below), token.json from a one-time Google login, a Slack bot token
python server.py
```

`.env`:
```
ANTHROPIC_API_KEY=...        # model fallback only; the deterministic layer runs without it
SLACK_BOT_TOKEN=xoxb-...
LEDGER_SHEET_ID=...          # a sheet with tabs `contacts` and `ledger` (see tests/fixtures.json for the shape)
GOOGLE_TOKEN_FILE=token.json # from google_auth_oauthlib InstalledAppFlow with the four scopes above
```

Use **Edge** for the voice path — it has the Natural voices; Chrome on Windows only has the 2012 ones.

### Docker
```bash
docker build -t occuris-echo .
docker run -p 8000:8000 occuris-echo                       # sandbox
docker run -p 8000:8000 -e ECHO_TWINS=0 --env-file .env -v $PWD/token.json:/app/token.json occuris-echo
```

## Production path — what a real deployment needs

This runs locally today, on purpose. To ship it:
1. **On-device speech recognition.** The browser's Web Speech API sends audio to Google/Microsoft. For an assistive tool handling medical appointments that's not acceptable; production would use Whisper locally or the OS speech engine.
2. **Per-user OAuth** with a verified Google app (currently testing mode, single test user) and per-user token storage.
3. **The ledger moves from Sheets to Postgres** — Sheets was chosen so the user can *read and edit their own memory*; keep that property with a UI over a real database.
4. Contacts from the user's real address book, with the same ambiguity rules.
5. **Testing with disabled users.** See below.

## Limitations — stated plainly

- **Not tested with disabled users.** Designed to WCAG 2.2 (2.5.8 target size, 2.2.1 no timing, 2.4.7 focus visible, 2.5.7 no dragging) and to documented guidance. That is not the same as tested.
- **Speech recognition is cloud-based** and the engine's confidence score is useless — Chrome reports 0.00 always, Edge 1.00 always (measured). Uncertainty is judged from the transcript's content.
- **The deterministic parser is English-only** and covers the intents in the fixture set. Off-script phrasing falls to the model, tagged as such.
- **"At 2" is assumed to mean 2pm** for hours 1–7 with no am/pm. It's stated in the echo, so it's catchable, but it's a heuristic.
- Fixtures are synthetic. The three from real testing are the only ones with a real utterance behind them.
- Built in six hours by one person. There are seams.
